## Headline, as measured

2026-08-27, simulated cohort, 200 subjects, subject-disjoint split, 40 test subjects.
Full tables in [`RESULTS.md`](RESULTS.md). The short version, because it is mixed:

| | SBP MAE | vs mean predictor | SBP bias (ME) | SBP r² |
|---|---|---|---|---|
| PINN | **17.69** | **+17.0%** | **−2.04** | **+0.169** |
| CNN (matched, no physics) | 19.48 | +8.6% | +8.29 | +0.032 |
| Ridge (classical PWA) | 19.86 | +6.8% | +8.99 | +0.026 |
| mean predictor | 21.31 | — | +7.86 | 0.000 |

**What went right.** The PINN beats the capacity-matched CNN on SBP by 1.8 mmHg, and beats it
far more convincingly on the two things that matter clinically: bias (−2.0 vs +8.3 mmHg) and
explained variance (r² 0.169 vs 0.032). The two share encoder, width, depth, optimiser and
schedule, so that difference is attributable to the physics and to nothing else.

The robustness result is the strongest one, and it landed where the design predicted. Under
**clipping** at severity 0.8 — which destroys the systolic peak while leaving the diastolic
decay intact — PINN 19.05, CNN 26.97, ridge 45.10. That is exactly the regime the physics was
meant to survive: amplitude information gone, timing and shape remaining. Across the whole
severity ladder the PINN degrades 17.6 → 19.6 mmHg (+11%) while ridge collapses 19.7 → 33.6
(+71%).

**What went wrong, and it matters.** *Physical parameter recovery essentially failed*:
R r=+0.28, SV r=+0.34, Tsys r=+0.15, HR r=0.00, and compliance **C r=−0.23, the wrong sign**.
The network is not recovering the physiology it appears to report. The Windkessel structure is
working as a useful reparameterisation and regulariser — it demonstrably improves accuracy,
bias and robustness — but the parameters it emits must **not** be presented as measurements of
a person's arterial compliance. The interpretability half of the abstract's claim is not
currently supported by evidence, and the report has to say so.

Two smaller honest notes: the CNN edges the PINN on DBP (13.28 vs 13.65), and `contact_loss`
did *not* defeat the models as predicted (PINN 18.35) — at severity 0.8 it blanks only part of
the window and the remaining beats stay readable.

Every model grades BHS D and fails the AAMI thresholds. On a between-subject task with no
per-user calibration that is the expected outcome rather than a bug, and it is why calibration
sits high on the roadmap.

## Where it stands

The full pipeline is built, tested and runs end to end on CPU. `pinnbp experiment` trains all
three models on identical data, sweeps robustness, checks parameter recovery, draws the
figures and regenerates `docs/RESULTS.md`.

- **73 tests pass** (`uv run pytest -q`), ruff clean. Physics is checked against closed-form
  results and an independent SciPy integration, not just for "runs without error".
- **Full numbers live in [`RESULTS.md`](RESULTS.md)**, generated by the experiment command and
  never hand-edited. Only the headline is repeated above, with its interpretation.
- **Everything reported so far is simulated.** That validates the pipeline and shows what is in
  principle recoverable. It is not clinical accuracy, and the docs say so wherever a number
  appears.

## The open threads, in priority order

See [`ROADMAP.md`](ROADMAP.md) for the full list. The four that matter:

1. **Explain or withdraw the interpretability claim.** Parameter recovery failed, compliance at
   the wrong sign. Either identify why — the likeliest explanation is that R, C and SV are not
   jointly identifiable from a single PPG site without a calibration anchor, since many
   parameter sets produce the same pressure waveform — or stop presenting the predicted
   parameters as physiological measurements. This outranks new datasets because it concerns a
   claim the abstract already makes.

2. **Run on PPG-BP.** Adapter and config exist; needs the download. Every number above is
   simulated until this happens.

3. **Report the no-physics ablation** (`configs/ablation_no_physics.yaml`). Same architecture,
   physics weights zeroed. It separates what the *architecture* contributes from what the
   *constraints* contribute — the PINN-vs-CNN gap above conflates the two.

4. **Multiple seeds.** Every number is one seed. The 1.8 mmHg SBP gap between PINN and CNN is
   not yet distinguishable from seed noise; the bias and r² gaps are large enough to be more
   convincing, but neither has an interval on it.

## Things that will bite you

- **`uv sync` may install the project non-editable.** If `import pinnbp` fails after a sync,
  run `uv pip install -e . --no-deps`.
- **Never compare measured tau to R·C absolutely.** It is ~4× low on a band-passed PPG. The
  loss constrains rank within a batch for this reason; see `ARCHITECTURE.md` finding 3.
- **Don't hand-edit `docs/RESULTS.md`.** Rerun `make experiment` (~26 min).
- **Check the timestamp on `RESULTS.md` before quoting it.** The quick config writes to the same
  paths, and a stale smoke run is easy to mistake for a real one.
- **The `quick` config's numbers are meaningless** (8 test subjects). It exists to prove the
  pipeline runs; its outputs are gitignored.
- **No GPU, ~1 GB free RAM.** Don't run a Gradle build or an emulator alongside a training run.
